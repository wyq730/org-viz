## 背景和目标

### 目标

> 整体目标。这部分不要修改。

根据已有的组织结构的数据，进行可视化：
- 首先，写一个脚本，输入一个 csv 文件，输出一个 json 文件。
  - 这个脚本是灵活的（不和 csv 里有哪些字段绑定）：它的输入除了 csv，还需要输入每个人的 id 列的列名 (id_column)，以及这个人上级 id 的列名 (parent_id_column)，
  - 输出的格式为:
    {
      "node": "用户的 open_id",
      "name": "用户姓名"
      "parent": "直属上级的 open_id, 如果没有则为空字符串",
      "abstract": [
        "性别, 工作城市",
        "部门完整路径",
      ]
      "other_info": {
        "入职": "入职日期",
        "邮箱": "邮箱，如 xxx@deeproute.ai",
        "手机号": "手机号，如 186xxx",
      }
    }
- 用一个纯前端的 web app：
  - 可以加载上述格式的 json 文件（拖拽进来），进行可视化。本质是根据 "parent" 字段确定各个 node 的连接关系，画出一个/多个树，每个节点显示：
    - name (较醒目的样式)
    - abstract: 在 name 下面，是一个数组，每个元素是一行。（比 name 的醒目程度弱一些的样式）
    - other_info: 点击这个 node 会在点击处出现一个弹窗，显示这些补充信息。
  - 注意这个 web app 对格式仅有如下要求，灵活性和通用性较好，理论上可以对任意 “一个树或多个树” 的结构进行可视化:
    ```
    {
      "node": "node 的 id",
      "name": "node 的名字，用于醒目显示"
      "parent": "parent node 的 id",
      "abstract": 一个数组，用于补充信息
      "other_info": 一个 object，其他信息，用于在弹窗里显示。
    }
    ```

## 方案

### 概要

- Python 标准库实现转换工具，不引入 Python 第三方依赖。
- 原生 HTML/CSS/JavaScript + SVG 实现前端，无构建步骤，无 CDN 或网络依赖，支持直接打开 index.html。
- JSON 顶层是节点数组，每条记录使用目标章节规定的五个字段。
- 以配置映射处理展示字段，提供适配现有员工 CSV 的示例配置，通用转换逻辑中不硬编码中文列名。

### 详情

> 描述方案详情，梳理每个模块做什么逻辑变动，不需要细化到每一行怎么改

#### CSV 转换工具

已新增 `scripts/csv_to_json.py`，接受输入/输出文件路径、`--id-column`、`--parent-id-column` 和 `--config`。配置中包含姓名列、摘要行定义和详情字段映射。摘要每行可以合并多列，例如把性别与工作城市以逗号连接；空值跳过。保留 ID 字符串，使用 utf-8-sig 读取 CSV、UTF-8 写入 JSON。

已新增 `configs/employees.json`：姓名映射到“姓名”；摘要两行分别为“性别 + 工作城市”和“部门完整路径”；详情映射为“直属上级 ← 直属上级”“入职 ← 入职日期”“邮箱 ← 邮箱”“手机号 ← 手机号”。ID 与上级 ID 列通过 CLI 传入 `open_id` 和 `上级open_id`。

转换时校验必需列、空 ID、重复 ID 和环；错误时给出行号或 ID，不覆盖已有输出。父 ID 缺失于文件时保留原关系、输出数量提示，前端将此类节点显示为独立树并标记缺失父节点。空文件或仅表头的文件报错。

#### 前端

已新增根目录 `index.html`、`web/styles.css`、`web/app.js`。首屏提供拖拽区、文件选择按钮及不含真实员工信息的演示数据入口；加载成功后展示文件名、节点/树数量及可缩放平移的树图。

渲染前独立校验 JSON 顶层数组、五个字段类型、ID 唯一性和无环关系。允许 abstract/other_info 缺省并补为空数组/对象，parent 的空字符串表示根。错误提示后保留先前有效视图。

使用 SVG 连接线与节点卡片，按父子层级自上而下排列，多棵树并排。节点 name 强调显示，abstract 每个元素一行；较长内容限制卡片尺寸，详情弹窗提供完整内容。默认显示前三层，初始以 85%（窄屏自动调整）的比例对准第一棵树的根，确保初始卡片可读；用“适应视图”查看全部已展开节点。支持逐节点展开/收起、缩放平移，以适应千人数据。

缩放与导航是首版核心交互：提供始终可见的放大、缩小按钮、当前缩放百分比、100% 原始比例及“适应全部已展开节点”按钮。支持滚轮缩放，以鼠标位置为缩放中心；拖动画布空白区域平移。展开/收起时保持操作节点在视口中的位置，不自动缩放整张图，避免展开后视图跳走。展开很多节点后，用户可以主动缩小或适应视图查看全局，再放大阅读局部；缩放只改变显示比例，不改变展开状态。缩放设置边界，但最小比例应允许完整展示当前样例的全部展开节点。

首版增加固定可见的姓名搜索框：搜索范围包括全部节点，包含折叠区域，支持忽略大小写的部分匹配及去除输入首尾空格。结果列表显示姓名、摘要及 ID 以区分同名节点，标明匹配数量，支持键盘上下选择、Enter 定位、Escape 关闭；无结果时明确提示。

选中搜索结果后自动展开目标节点的全部祖先路径，保持其他分支展开状态，将目标平滑居中到可阅读的缩放比例，并高亮节点。仅输入关键词不改变树布局；清空搜索移除搜索高亮，保留展开状态与视图位置。节点详情仍通过点击节点打开，避免搜索结果定位后弹窗遮住目标。

节点的下级按钮同时显示“直属 N · 全部 M”，全部人数为所有层级的后代人数，不包含当前节点；导入时自底向上计算一次，折叠不改变统计。

点击节点主体在点击处打开详情弹窗，显示 other_info；弹窗限制在视口内，点击外部或 Escape 关闭。展开按钮与查看详情分开。文字通过 textContent 渲染，避免把导入的数据当成 HTML。

#### 使用说明和样例

新增 `README.md`，说明 CLI 参数、配置格式、JSON 协议和前端操作；新增人工构造的小型 `examples/demo.json`。真实员工 JSON 由用户运行转换工具按需生成，不写入公共演示或页面源码。

### 关键点

> 本方案里的一些关键决策点

- 首版无后端，不上传用户文件，也不部署；页面可离线使用。
- 关系 ID 和展示字段分别配置，避免数据源与前端耦合。
- 既支持多根树，也支持缺失父节点的子树；环和重复 ID 明确拒绝。
- 手机号依照现有数据原值映射，可通过配置移除任意详情字段。
- 保留目标章节原文；其中 JSON 示例省略的逗号在实际输出中补齐，节点集合使用顶层数组。
